1. Executive Summary & Approach

This project implements a test Digital Identity Wallet Progressive Web App (PWA) for the UIDAI Sandbox according to the official technical specification. The application empowers users to manage verifiable identity documents (Aadhaar, PAN, Driving Licence), securely inspect masked credentials with strict automated lifetime controls, and maintain 100% offline functionality via a dedicated Service Worker caching layer.

Core Architecture Tenets:
  • Predictable State Machine: Pure unidirectional state flow via React Context and useReducer, eliminating race conditions across loading, error, empty, and success states.
  • Defensive Security Lifecycle: Plaintext identifiers are decrypted into component memory only upon explicit user gesture and are guaranteed to be purged from memory and DOM after exactly 10 seconds.
  • Accessible by Design: Compliant with WCAG 2.1 AA standards featuring full keyboard operability, explicit ARIA state declarations, and polite screen-reader announcements.
  • Resilient Offline PWA: Service Worker intercepts GET /api/credentials using a Network-First strategy with Cache API fallback and metadata header tagging (X-Wallet-Cache: offline).

2. Part 1: Credential Dashboard & State Management

The credential dashboard fetches mock credentials from GET /api/credentials (served via mock Vite server middleware). State is modeled as a formal discrete finite state machine managed with a typed reducer.

State Trigger / Action UI Representation
idle / loading FETCH_START Animated SVG shimmer skeleton cards mirroring the exact layout
success FETCH_SUCCESS Responsive 3-column credential card grid with smart chip insignia
empty FETCH_EMPTY Zero-state illustration with guidance and "Check again" trigger
error FETCH_ERROR Descriptive failure alert with retry button & status recovery

Layout Responsiveness: Built with CSS Grid and Flexbox:

  • Mobile (<640px): Stacked 1-column layout with 48px+ touch targets for thumb-friendly mobile interaction.
  • Tablet (641px–1024px): 2-column balanced grid with accessible card headers.
  • Desktop (>1024px): 3-column expansive view with live sandbox controls, network status pill, and statistics strip.

3. Part 2: SecureDataMask Component & Security Threat Model

The SecureDataMask component solves the core privacy requirement: sensitive identifiers (Aadhaar, PAN, DL) must never remain permanently visible on screen or linger in the DOM tree.

Default Masked State:
  • Shows only the last 4 characters in the canonical pattern: XXXX-XXXX-1234.
  • Full plaintext is absent from the DOM (verified via test assertions).
  • Screen readers hear: "Aadhaar number hidden, ending in 0123."
Revealed State (10s Window):
  • "Tap to Reveal" stores full plaintext in local state revealedPlaintext.
  • Smooth 60fps CSS hardware-accelerated timer bar counts down 10 seconds.
  • Polite live region announces reveal event to assistive technology.

Security Purge Lifecycle & Defensive Triggers:

When the value is re-masked, setRevealedPlaintext(null) is executed immediately. The full value is completely cleared from memory and unmounted from the DOM:

  • 10-Second Expiry: A managed setTimeout triggers automatic conceal at exactly 10,000ms.
  • Manual Conceal: Clicking "Hide" instantly clears plaintext state and resets the timer.
  • Visibility API (Tab Switch / Screen Lock): Listening to document.visibilityState === 'hidden' ensures that switching tabs or minimizing the browser immediately conceals sensitive data.
  • Escape Key Dismissal: Accessible Escape key handler allows instant keyboard concealment.
  • Component Unmount: Cleanup effect clears pending timers to prevent memory leaks or dangling callbacks.

4. Part 3: Offline Support, PWA & Service Worker

Offline capabilities are powered by public/sw.js, implementing a Network-First caching strategy tailored for financial and identity credentials: 

Client Request: GET /api/credentials?scenario=success
   │
   ├──> [1] Try Network (Fetch)
   │       ├── 200 OK: Cache response clone under canonical key ('/api/credentials')
   │       └── Error / Disconnected: Catch network exception
   │
   └──> [2] Fallback to Cache API: caches.match(cacheKey)
           ├── Found: Inject header 'X-Wallet-Cache: offline' & return cached 200 OK
           └── Not Found: Return synthetic 503 Service Unavailable JSON

5. Testing Strategy & Verification

Automated test coverage is implemented in Vitest with React Testing Library and @testing-library/user-event. The suite runs with 0 warnings and 0 errors across 41 unit and contract tests:

  • SecureDataMask.test.tsx (18 tests): Uses fake timers (vi.useFakeTimers()). Asserts that the identifier is visible at 9,999ms, concealed at exactly 10,000ms, immediately re-masked if the secret prop changes while revealed, and verified completely purged from container.innerHTML.
  • Dashboard.test.tsx (4 tests): Tests in-flight loading state, success data rendering, empty wallet zero-state, and error state recovery on retry click.
  • credentialsNetworkFirst.test.ts (6 tests): Validates caching of 200 OK responses, refusal to cache 500 errors, cache fallback on network drop, and 503 handling when cache is cold.
  • sw.contract.test.ts (3 tests): Enforces contract rules on public/sw.js.
  • credentialsReducer.test.ts (4 tests) & maskSensitiveValue.test.ts (6 tests).

6. Assumptions & Sandbox Scope

  • Sandbox Identifiers: Identifiers used (e.g. 2345 6789 0123, ABCDE1234F) are fictional test values for sandbox validation.
  • State Separation: In compliance with the prompt, the "clear from component state" security rule is strictly isolated within the SecureDataMask component layer.
  • PWA Interception: The service worker intercepts /api/credentials while preserving Vite HMR in local development.
